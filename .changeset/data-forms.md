`octane/data` adds native forms. A write that declares `form` fields, such as `form: { title: 'text' }`, can be submitted by a plain HTML form, which works before hydration and with JavaScript off. `useForm(write, key?)`, from `octane/data/octane` and `octane/data/react`, returns the form's attributes and hidden fields, plus its pending state, submitted values and field issues. Once hydrated, the same form submits through the store with the write's optimistic edit, and it resets on success unless it was edited meanwhile. `key` gives each row its own state. On the server, `forms(request)` runs a native submission and answers 303 back to the page, or returns the values and issues for the page to render again. The data handler's new `secret` and `grant` options sign each page's forms for its account, so a form rendered for one account is refused for another. Field codecs (`text`, `secret`, `number`, `boolean`, `checkbox`) refuse missing, repeated and unknown fields, and a `secret` field is never sent back to the page. The store's `dehydrate()` output now also carries the page's form state, which only that method produces and only `createDataStore({ seed })` reads.
