<h2 id="scoped-by-default">Scoped by default</h2>

Write CSS next to the markup it styles. A block is a child of an element or a
fragment, and it styles the other children of that list and their descendants — never
the element that contains it. The compiler rewrites every selector with a hash, stamps
that hash on each element the block reaches, and registers the sheet once per module.
Rules never leak into a parent, an outer sibling, a child component, or the page
around it:

```tsrx
export function Card(props) @{
	<>
		<style>
			.card {
				padding: 1.5rem;
				border: 1px solid var(--line);
			}
			h2 {
				margin: 0 0 0.5rem;
			}
		</style>
		<article class="card">
			<h2>{props.title as string}</h2>
			<p>{props.summary as string}</p>
		</article>
	</>
}
```

The block compiles to `.card.tsrx-1a20093c { … }` and `h2.tsrx-1a20093c { … }`, and
both elements carry `tsrx-1a20093c` in their class list. A `<style>` block holds
static CSS: no `{expr}` holes, no template statements. Put runtime values in custom
properties (`style={{ '--tone': tone }}`) and read them with `var(--tone)`. Wrap a
selector in `:global(…)` to opt one rule out of scoping.

To style an element, make the block and the element siblings in a fragment, as above.
A block written inside `<article>` would style the article's other children and not
the article itself. A `@{ … }` body and every directive arm hold setup statements and
exactly one output node, and a block is an output node like any other: a block beside
the output node is the multiple-outputs parser error, and a lone block as the output
styles nothing (`STYLE_STANDALONE_NEEDS_FRAGMENT`). Wrap the block and the output in
`<>…</>`. The only attributes a scoped block accepts are `ref` and `apply`.

<h2 id="scopes">What a scope is</h2>

Scopes are lexical. Every children list that holds at least one block is a scope, and
a block belongs to the list it is written in:

- The children of a native element.
- The children of a fragment — including the fragment a `@{ … }` block or a directive
  arm (`@if`, `@else if`, `@else`, `@for`, `@empty`, `@case`, `@default`, `@try`,
  `@pending`, `@catch`) renders.
- The children of an element or fragment used as a value: an assigned template, or the
  value of a `{ … }` hole, written inside a component body.

Every element carries the hash of each scope that encloses it, outermost first, so an
outer block's rules reach into nested scopes while an inner block's rules never reach
out. Stamping stops at composite components and function boundaries: a child
component's own elements, and elements returned from a callback such as
`items.map((item) => <li />)`, belong to no scope of the parent.

```tsrx
export function Panel() @{
	<>
		<style>
			div {
				color: black;
			}
		</style>
		<div class="outer">Black</div>
		@{
			<>
				<style>
					div {
						font-weight: bold;
					}
				</style>
				<div class="inner">Black and bold</div>
			</>
		}
	</>
}
```

With `A` and `B` as the two hashes, the compiled classes are `outer A` and
`inner A B`. The nested `div` matches both rules; the outer one matches only its own.

<h2 id="multiple-blocks">Several blocks, one scope</h2>

Blocks written among the same children share one hash and render as one injection. Use
that to keep a rule next to the element it styles instead of collecting every selector
at the bottom:

```tsrx
export function Toolbar() @{
	<>
		<style>
			.toolbar {
				display: flex;
				gap: 0.5rem;
			}
		</style>
		<div class="toolbar">
			<style>
				.save {
					font-weight: 600;
				}
			</style>
			<button class="save">Save</button>
			<style>
				.cancel {
					opacity: 0.7;
				}
			</style>
			<button class="cancel">Cancel</button>
		</div>
	</>
}
```

The two blocks inside the toolbar compile into a single sheet in source order and
style the buttons beside them; the `.toolbar` rule sits beside the toolbar in the
fragment because a block never styles the element that contains it. A scope's blocks
are always emitted together as one contiguous group, even when other scopes sit between
them in the source.

<h2 id="control-flow">Control flow: stamping follows the branch, CSS does not</h2>

A block inside a directive arm's fragment is scoped to that arm, so the same class name
can mean different things in `@if` and `@else`. The compiler still emits the CSS of
every arm whichever branch renders; only the class stamping is conditional. Do not rely
on a branch's rules being absent from the page, and keep a rule that must apply
everywhere in an enclosing scope:

```tsrx
export function Status(props) @{
	<>
		<style>
			.status {
				padding: 0.5rem;
			}
		</style>
		<section class="status">
			<style>
				.title {
					font-weight: bold;
				}
			</style>
			<h2 class="title">Status</h2>
			@if (props.ready) {
				<>
					<style>
						.ok {
							color: green;
						}
					</style>
					<p class="ok">Ready</p>
				</>
			} @else {
				<>
					<style>
						.wait {
							color: gray;
						}
					</style>
					<p class="wait">Waiting</p>
				</>
			}
		</section>
	</>
}
```

With `A`, `B`, `C`, and `D` as the hashes of the four scopes — the outer fragment, the
section's children, and the two arms — the compiled classes are `status A`,
`title A B`, `ok A B C`, and `wait A B D`, and the sheets are emitted in that order. The
`.ok` and `.wait` sheets are both registered when the module loads, and `.ok` cannot
reach the waiting paragraph or vice versa. A `.status` rule written inside the section
would match nothing: the section is not in its own children's scope.

<h2 id="class-maps">
	Class maps and <code>$class</code>
</h2>

Assign a `<style>` block to a variable and the initializer becomes a plain object
instead of a scoped block. The object has `$class` — the block's scope hash, preceded
by the classes of any theme it applies — plus one key per class selector whose value
is the hash and the class name together. It can live at module scope or anywhere a
declaration is legal inside a component body:

```tsrx
export const theme = <style>
	div {
		color: green;
	}
	.dark {
		color: purple;
	}
</style>;
// theme.$class → 'tsrx-fe4e37b1'
// theme.dark   → 'tsrx-fe4e37b1 dark'

export function Badge(props) @{
	<span class={theme.dark}>{props.label as string}</span>
}
```

Pass these strings to child components as ordinary props; the hash is already in
them. `$class` is reserved, so a block cannot declare a `.$class` selector.

A block that is exported, applied, or whose `$class` is read anywhere in the module is
a theme and keeps every selector, element and descendant selectors included. A local
block that is none of these is a class map: only its standalone class selectors
survive, and the rest are dropped as `/* (unused) … */` comments in the compiled CSS.
A standalone `<style>` at module scope is an error; assign it to a variable there.

<h2 id="apply">Apply a theme to a scope</h2>

`<style apply={theme} />` stamps the theme's `$class` on the items beside it and
everything below them — the same elements a block's own rules reach, never the element
that contains it — so the theme's element and descendant rules reach those elements as
if the theme had been written there. A self-closing apply adds no hash of its own; a
bodied `<style apply={theme}>…</style>` applies the theme and declares the scope's own
block in one tag:

```tsrx
// theme.tsrx
const base = <style>
	div {
		font-family: system-ui;
	}
</style>;

export const theme = <style apply={base}>
	div {
		color: green;
	}
	.dark {
		color: purple;
	}
</style>;
// theme.$class → base's hash, then theme's own hash
```

```tsrx
// Panel.tsrx
import { theme } from './theme.tsrx';

export function Panel() @{
	<>
		<style apply={theme}>
			div {
				color: black;
			}
		</style>
		<span class={theme.dark}>Purple</span>
		<div>Black: the local rule beats the theme's green</div>
	</>
}

export function Card() @{
	<>
		<style apply={theme} />
		<article>
			<h2>Green, system-ui</h2>
		</article>
	</>
}
```

- `apply={[a, b]}` applies several themes in order, and a theme can apply another:
  its `$class` then lists the applied classes first and its own hash last.
- `export const bundle = <style apply={[a, b]} />;` composes themes with no CSS of its
  own; `bundle.$class` is the two themes' classes.
- A theme declared in the same module is inlined as a string literal, so the element's
  static template stays hoisted. An imported theme is read at runtime through
  `theme.$class`, which turns that element's class into a template literal.
- A theme must be declared before the block that applies it.

An element's final class list is: authored classes, enclosing scope hashes outer to
inner, then applied theme classes.

<h3 id="class-opt-in">
	Opt single elements in with <code>$class</code>
</h3>

`apply` is the whole-scope form. When only some elements should pick up a theme, give
those elements `class={theme.$class}` and leave `apply` out: the theme's element and
descendant rules match exactly the elements that carry the class, and their siblings
stay untouched. Because `$class` is a plain string, a child component can receive it
through a prop and stamp its own elements; the passed class lands before the child's
own scope hash.

```tsrx
function Card({ parentClass }: { parentClass: string }) @{
	<>
		<style>
			.local {
				padding: 0;
			}
		</style>
		<article class={parentClass}>
			<h2 class={parentClass}>Blue, from the parent's theme</h2>
		</article>
	</>
}

export function App() @{
	const theme = <style>
		div,
		h2 {
			color: blue;
		}
		.card {
			color: red;
		}
	</style>;
	<>
		<Card parentClass={theme.$class} />
		<div class={theme.$class}>Blue: opted in</div>
		<div class={theme.card}>Red: a class entry carries the hash too</div>
		<p>Untouched</p>
	</>
}
```

Reading `theme.$class` is what makes `theme` a theme: the `div, h2` rule survives even
though nothing exports or applies the block. A block whose only reads are class entries
such as `theme.card` stays a class map and drops its element selectors. Opt one element
into several themes with `class={[a.$class, b.$class]}`, the counterpart of
`apply={[a, b]}`; the two forms compose, so a scope can apply a base theme while single
elements opt into an accent.

<h2 id="ordering">Ordering guarantees</h2>

CSS is emitted in lexical pre-order, and at equal specificity the rule emitted last
wins. A scope's sheet sits where its first block is, after the assigned blocks
declared before it in the enclosing statement list and before the scopes and assigned
blocks nested inside it. Sibling scopes follow source order, and an applied theme's sheet is emitted
before the block that applies it, so a local rule wins over the theme at equal
specificity.

The compiled module carries one `injectStyle(hash, css)` call per scope. Where it
runs depends on the runtime:

- **On the client**, every call sits at module scope and runs when the module is
  evaluated, in the emission order above. The runtime deduplicates by hash, appends
  one `<style data-octane="hash">` element per sheet to `<head>`, and skips a sheet
  the server already sent.
- **On the server**, the calls sit at the top of each component body, so a request
  collects only the sheets of components it actually rendered. An assigned block
  injects its sheet when the request reads it — a component that applies an
  imported theme touches the theme before its own sheets, so the theme still
  precedes the scope that applies it, even across modules. Buffered renderers
  return them as the `css` field of the result, deduplicated by hash in injection
  order; the streaming renderers have no `css` field and flush each scoped
  `<style data-octane>` tag inline with the content that uses it.

Bundlers do not see this CSS: it rides inside the compiled JavaScript rather than a
virtual CSS module, so CSS plugins, PostCSS, and `build.cssMinify` never touch it.
Global stylesheets that every component reads, such as design tokens, belong in a
`.css` file the page links.

<h2 id="float">Head resources are outside the model</h2>

A `<style href="…" precedence="…">` is a Float resource: the runtime hoists it into
`<head>` and deduplicates it by `href`, and it is not a scoped block. It accepts no
`apply`, gets no hash, and never stamps a class. The same is true of a `<style>`
rendered inside `<head>`.

<h2 id="diagnostics">Diagnostics</h2>

Style errors stop the compile. Each carries one of these codes, which `octane analyze`
prints under the message and the bundler plugins surface in their own error output:

- `STYLE_APPLY_VALUE` (`tsrx-style-apply-value`): `apply` needs an expression value —
  `apply={theme}` or `apply={[a, b]}`.
- `STYLE_APPLY_TARGET` (`tsrx-style-apply-target`): an `apply` entry is not an
  identifier, member expression, or array of those, or does not resolve to a style
  block.
- `STYLE_APPLY_BEFORE_DECLARATION` (`tsrx-style-apply-before-declaration`): the applied
  theme is declared after the block that applies it. Move the theme above.
- `STYLE_APPLY_DUPLICATE` (`tsrx-style-apply-duplicate`): two `apply` attributes on one
  block. Pass several themes as one array.
- `STYLE_APPLY_UNSUPPORTED_HOST` (`tsrx-style-apply-unsupported-host`): `apply` on a
  `<head>` style or an `href` resource style.
- `STYLE_RESERVED_CLASS_KEY` (`tsrx-style-reserved-class-key`): an assigned block
  declares a `.$class` selector. Rename it.
- `STYLE_STANDALONE_AT_MODULE_SCOPE` (`tsrx-style-standalone-at-module-scope`): a
  bare standalone `<style>` statement at module scope. Assign it to a variable.
- `STYLE_STANDALONE_OUTSIDE_TEMPLATE` (`tsrx-style-standalone-outside-template`): raw
  CSS in a `<style>` outside every `@{ … }` or `@if`/`@for`/`@switch`/`@try` body — a
  plain function returning JSX, or an element assigned at module scope. Use
  `<style>{css}</style>` in TSX, or assign the block.
- `STYLE_STANDALONE_NEEDS_FRAGMENT` (`tsrx-style-standalone-needs-fragment`): a
  `<style>` as the lone output of a `@{ … }` or directive body. Wrap it with the output
  it styles in a fragment: `<><style>…</style><div>…</div></>`.
- `STYLE_UNKNOWN_ATTRIBUTE` (`tsrx-style-unknown-attribute`): an attribute other than
  `ref` and `apply` on a scoped block.
- `CSS_GLOBAL_PLACEMENT` (`tsrx-css-global-placement`): `:global(…)` used where the
  scoping rules do not allow it.
