# TanStack DB upstream

`@octanejs/tanstack-db` adapts the complete React binding of
`@tanstack/react-db@0.3.8` over the published, framework-neutral `@tanstack/db@0.9.0`.
The core is imported directly. React and its testing tools are development dependencies.

`audit/upstream.lock.json` verifies all 30 files of the immutable package tree.
`upstream/` is byte-exact; `tests/upstream/` is generated by the materializer from
mechanical rewrites and the committed StrictMode exclusion. Six MIT shared test
helpers are pinned separately in `audit/upstream-helpers.json`. They access the
installed DB core source in isolated parity projects so Collection identity agrees.
No neutral runtime implementation is copied into the published binding.

## Source boundary

The copied React adapter occupies `src/` except for authored `src/slot.ts`.
The published DB core is imported unchanged; no core implementation or React
shim is copied. Native Octane external-store hooks provide the subscription
contract required by the adapter. Shared upstream test helpers are audit-only.

## Owned surface

| Surface | Octane implementation |
| --- | --- |
| `useLiveQuery` and configuration/status types | All pinned overloads, derived identity, explicit query keys, provider/client selection, observer snapshots and warnings |
| `useLiveInfiniteQuery` and its types | Shared core window controller, replacement, paging promises and cleanup |
| `useLiveSuspenseQuery` | Pinned preload promise, rejection, streaming identity and stale-data behavior |
| `useLiveQueryEffect`, `usePacedMutations` | Native effect/callback lifecycles over imported core operations |
| `DbProvider`, `useDbClient`, `useOptionalDbClient` | Native context; children accept `OctaneNode` |
| `HydrationBoundary` and its props | Applies state before children and follows changed state/client; children accept `OctaneNode` |
| All `@tanstack/db` exports | Direct unchanged re-exports |

Octane hook-slot plumbing is confined to the adapter. Development warning stacks
omit compiler bridge frames before identifying the consumer callsite. The runtime
now checks external-store snapshots after subscribing, so the previous binding
microtask workaround is removed.

## Evidence

The immutable inventory contains 161 runtime and 18 type registrations, all
crosswalked in `audit/registrations.json` and `audit/crosswalk.json`. The pristine
React suite executes all 161 cases; the adapted suite executes 160 cases. The
single StrictMode double-invocation case is inapplicable under Octane's documented
contract. Every ordinary initialization, query, effect, mutation, paging, provider,
hydration and cleanup assertion is retained.

Both type suites compile the two exact upstream type files, with mechanical
import/renderer mappings for the adapted side. Public type probes cover the full
value export set, hook signatures, owned types, native children and invalid inputs.
Native tests additionally retain the older integration scenarios. The synchronous
pagination assertion was updated to await the new fetch promise after the same
old assertion failed against the pinned React release.

The parity manifest records executable lanes and content hashes. SSR/hydration
checks use real server/client compilation and DOM identity, and the differential
fixture runs the same provider/data/client changes through both renderers.
