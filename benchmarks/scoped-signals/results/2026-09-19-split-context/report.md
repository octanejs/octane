# Private Context provenance through split hydration

The production compiler keeps its existing closed-module Context proof when `<Hydrate>` extracts a child module. It certifies exact original provider tags and generated capture binding IDs, then selects the existing private Context factory and compiled provider policy only when the renderer's lexical resolver confirms the same binding. Exported/escaped/shadowed Contexts and authored `children`, spread, namespace or `__*` capture overrides remain general. No runtime, package export, signal policy or public ABI changes.
